# Micro-Turn Basketball

## 목적과 실행

`/basketball`은 메인 헤더의 **농구** 탭이다. 브라우저 로컬에서 작동하는 하프코트 1:1 전략 게임으로, 계정·백엔드·온라인 매칭·물리 엔진이 필요 없다. 기존 전역 헤더의 방문자 요청 및 외부 폰트는 기존 사이트 기능이며 농구 엔진의 의존성이 아니다.

```sh
cd frontend
npm ci
npm run dev
# http://localhost:3000/basketball
```

한 포제션의 **드리블 행동 단위 3개 제한**은 이 게임의 특별 규칙이다. 공이 바닥에 튀는 횟수도, 공식 농구 규칙도 아니다. 이동·거리·선점은 결정론적으로 계산하고 공 제어 실패·슛·스틸 등 불확실한 사건에 시드 난수를 사용한다.

## 경기 흐름

체크볼 → 두 선수의 비공개 명령 선택 → 제출 검증 및 잠금 → 공통 시간축 시뮬레이션 → 결과 공개 → 다음 의사결정. 득점·정상적인 수비 성공으로 공격이 끝나면 선수 정체성은 유지하고 공격/수비 역할을 교대한다. 공격 리바운드와 원공격자의 루즈볼 회복은 같은 포제션이다.

## 네 가지 모드

- 인간 선공: 사용자가 P1을 조작하고 P2가 AI. 소유권이 바뀌면 사용자가 수비한다.
- 인간 후공: 사용자가 P2를 조작하고 P1이 AI. 소유권이 바뀌면 사용자가 공격한다.
- 로컬 2인: 한 화면에서 순서대로 입력하되 첫 선수 제출 후 가림 화면으로 넘긴다.
- AI 자동: 같은 관찰·검증 API로 두 선수가 선택한다. 한 의사결정씩 진행하거나 자동 재생한다.

이름이나 모드에 따른 판정 보너스는 없다. 난도는 AI 선택에만 영향을 준다. 조작자가 역할을 고정해서 공격만 반복하지 않는다.

## 책임 분리

- `src/lib/basketball`: 순수 TypeScript, 경기 상태·규칙·행동·공간·AI·리플레이·통계
- `src/app/basketball`: Next 페이지, React 입력, SVG 코트, 리플레이 및 Web Worker 통계
- `tests/basketball`: 엔진 계약·규칙·속성·대칭성 회귀 테스트
- `scripts/basketball`: 독립 컴파일/통계 실행
- `docs/basketball`: 설계, 수식, 검증 증거, 초기 모델의 한계

UI는 명령 API의 반환 상태를 렌더링한다. 게임 진행 중 좌표·점수·체력을 UI에서 직접 수정하지 않는다. 새 경기의 설정·선수 능력치를 바꾸는 것은 새로운 초기 상태 생성이다.

## 모델의 의미

이 모델은 설명 가능하고 재현 가능한 초기 논리 시뮬레이션이다. NBA 실측 데이터에 보정된 물리/통계 모델이라고 주장하지 않는다. 밸런스는 실제 실행 표본과 함께 평가하며, 기술을 눌렀다는 사실만으로 돌파를 성공시키지 않는다.
