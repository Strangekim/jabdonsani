# INK v0.2

## 실행

- 웹: /ink (메인 헤더의 INK 탭)
- 개발: frontend에서 npm run dev
- 규칙 테스트: frontend에서 node --test tests/ink/*.test.mjs

기존 Next.js 16, React 19, Three.js, CSS Modules를 사용한다. 새 패키지나 환경 변수, DB 마이그레이션은 없다.

## 확정 규칙

- 2~8인 로컬 핫시트 및 AI 혼합 대전, 턴당 2 AP. 한 행동 1 AP, 남은 AP를 포기할 수 있다.
- 시작 플레이어를 라운드마다 한 자리 순환한다. 라운드는 반드시 인원수의 배수이며 고정 라운드 이후 종료한다.
- 원형 맵, 기본 면적 8 × 인원 × 라운드. 지름은 소수점 첫째 자리의 반지름으로 보정한다.
- 기본 4인 / 8라운드 / 지름 18. 인원, 순환 횟수, 면적 계수를 경기 시작 시 선택한다.
- 같은 색 잉크는 누적되고 다른 색은 상쇄된다. 이미 칠한 잉크는 이동하거나 회수할 수 없다.
- 농도 0.5 이상인 자기 색의 노출 표면적만 점수로 집계한다. 잠복 잉크 자체는 0점이다.
- 소유 면적이 최대인 사람이 승리한다. 동점은 공동 1위다.

## 초기 실험값

| 도구 | 시작 조건 / 이동 | 폭 또는 반경 | 잉크 예산 |
|---|---|---|---|
| 붓 | 자신의 영토, 표면 경로 3 | 폭 약 1 | 9 |
| 잉크 건 | 농도 2.5 이상 자기 영토, 직선 5 | 반경 0.56 | 9 |
| 잉크 폭탄 | 고정 본진, 낮은 5.5 / 높은 4.2 포물선 | 반경 1.25 | 5 |
| 공중 투하 | 맵 어디든, 수직 | 반경 0.85 | 3 |
| 잠복 잉크 | 자기 영토 1.5 이내, 중립 패치 하나 | 패치 1개 | 경기당 3회 |

잉크 총량 9라는 일반 도색 기준에서 폭탄/공중 투하는 일부가 소실되는 실험 모델이다. 실제 도달 예산보다 더 많은 잉크가 생성되지 않는다(부동소수점 반올림 오차 제외). 무기 사용 횟수와 일반 잉크 보충/저장 시스템은 별도 설정하지 않고 AP로 제한한다. 잠복 잉크는 상대가 그 표면에 도색할 때 해당 표면의 도달량을 설치자 색으로 바꾸고 한 번 소멸한다. 설치 횟수는 공개하고 위치는 소유자만 확인한다. 같은 표면에 여러 명이 설치하면 먼저 설치된 상대의 잠복 잉크만 발동한다.

건물은 플레이어별 종류당 1개, 지면에서만 건설한다. 건물 바닥의 실제 접촉 영역으로 근사한 패치가 중립 또는 자기 영토여야 하고 상대 영토·본진·다른 구조물과 겹칠 수 없다. 소유권 최소 농도(0.5)에 미달한 표면은 중립으로 취급한다. 가려진 바닥의 잉크와 잠복 잉크는 소멸하고 새 표면은 중립이다. 건설 시 기존 자기 영토의 면적만 점수에서 차감한다.

- 돔: 반지름 1
- 타워: 반지름 0.5, 높이 3
- 장벽: 길이 3, 높이 2, 두께 0.5
- 아치: 너비 3, 높이 3, 깊이 1

## 코드 경계

| 경로 | 책임 |
|---|---|
| src/lib/ink/geometry.mjs | 표면 메시 생성, 충돌, 표면 경로 |
| src/lib/ink/engine.mjs | 상태 생성, 명령 검증, 판정, 턴, 점수, 비공개 정보 처리 |
| src/lib/ink/engine.d.mts | 명령, 공개 뷰, 미리보기, GamePort 타입 |
| src/app/ink/InkClient.tsx | 로비, 행동 선택, 로컬 포트 연결, 핫시트 |
| src/app/ink/InkBoard.tsx | Three.js 렌더링, 카메라, 표면 선택 |
| tests/ink/engine.test.mjs | DOM 없는 규칙 회귀 테스트 |

엔진은 React, Three.js, 브라우저 API, 외부 패키지에 의존하지 않는다. GamePort가 UI와 엔진의 경계다. 로컬 구현은 동기식이며 원격 구현에서는 서버 응답을 기다리는 비동기 어댑터로 변경한다.

## 서버 이관

현 단계에서는 서버, 온라인 대전, 로그인, 랭킹을 추가하지 않는다. 이후 엔진 모듈을 backend/ink 또는 공용 패키지로 옮겨 서버가 유일한 권위 상태를 보유하도록 구성한다. 기존 Express에 방 생성·입장·행동 제출·재접속 기능과 WebSocket 이벤트를 추가할 수 있다.

- 클라이언트는 Command와 expectedVersion만 전송한다.
- 서버는 로그인/방 소속/현재 행동자/버전을 확인하고 apply를 실행한다.
- 서버는 view(state, authenticatedPlayerId)만 전송한다. 원본 state, 상대 함정 위치, 실제 숨은 결과를 포함한 미리보기는 전송하지 않는다.
- 중복 명령, 동시 요청, 재연결은 서버에서 직렬화하고 버전 불일치를 거부한다.
- 핫시트 화면의 위치 가리기는 동일 브라우저에서의 편의 기능이지 보안 경계가 아니다.

## 알려진 프로토타입 한계

곡면은 분할된 메시의 실제 삼각형 면적과 0.5 간격 지면 패치로 근사한다. 건물 바닥 소유권은 표본 중심을 사용하고, 표면 경로와 투척은 결정론적 근사 모델이다. 실제 유체/물리 엔진이 아니다. 렌더링과 점수는 동일한 면적 데이터를 사용하므로 미리보기와 판정의 규칙은 일치하지만 숨은 잉크는 미리보기에서 제외한다. 작은 맵의 표본 해상도 때문에 초기 면적의 미세한 편차가 있을 수 있다. 실제 3D 게임의 맵 크기와 무기 밸런스는 추가 플레이테스트가 필요하다.

## AI 대전

로비에서 각 좌석을 사람, 균형형, 확장형, 공격형, 건축형 AI 중 선택한다. 혼자 대전, 전원 사람, 전원 AI 프리셋이 제공된다. AI 턴은 자동 진행되며 관전 중 일시정지, 재개, 오류 시 재시도 또는 턴 넘기기를 지원한다.

- 일반 모드: 공간별 유망 후보를 추리고 동일 게임 엔진의 preview로 평가한다. 첫 행동 상위 3개와 가장 좋은 건설 후보에 대해 두 번째 행동을 탐색한다. 실제 첫 행동을 반영한 후 남은 AP를 다시 평가한다.
- 빠른 AI: 후보 수를 줄이고 한 행동만 평가한다.
- 모든 성향은 실제 소유 면적, 상대 점수 감소, 잉크 약화, 발사 지점 확보, 건설의 장기 가치 등에 가중치를 다르게 적용한다.
- AI에는 현재 플레이어의 공개 뷰와 자신의 잠복 잉크만 전달한다. 가상 시뮬레이션은 보이지 않는 상대 함정을 모르는 상태에서 실행된다.
- 계산은 Web Worker에서 실행하고 실제 행동은 GamePort.dispatch로 기존 검증과 판정을 거친다. 잠복 잉크의 설치 위치는 AI 관전 화면에 표시하지 않는다.
- 학습 모델이나 외부 API는 없다. 후보 제한과 휴리스틱 기반의 테스트 상대이며 모든 행동 조합의 최적해를 보장하지 않는다.

| 경로 | 책임 |
|---|---|
| src/lib/ink/ai.mjs | 공개 뷰 복원, 행동 후보 생성, 성향별 평가 및 2 AP 탐색 |
| src/lib/ink/ai.d.mts | AI 타입 계약 |
| src/lib/ink/ai.worker.mjs | 브라우저 백그라운드 계산 |
| tests/ink/ai.test.mjs | 행동 유효성, 정보 비공개, 연계 탐색, AI 완주 검증 |

충돌 판정은 지면 공간 해시와 구조물 패치의 경계 상자 검사를 사용해 후보 평가 비용을 줄인다.
