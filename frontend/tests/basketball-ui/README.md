# 농구 화면 통합 테스트

## 실행

```bash
npm run test:basketball-ui
# 또는 npm 옵션 전달 구분자를 사용한다.
npm exec -- vitest run --config vitest.basketball.config.ts
```

`vitest.basketball.config.ts`는 이 디렉터리만 수집하므로 `node:test` 기반 엔진 테스트와 충돌하지 않는다. 테스트는 Node.js 24에서 실행했으며 실제 `BasketballClient`, 자식 컴포넌트, 순수 TypeScript 경기 엔진을 함께 사용한다. 고정 시드 `20261013`의 경기 결과를 모의 구현하지 않는다. UI에서 저장한 JSON을 실제 엔진으로 재실행해 상태와 명령을 확인한다.

## 검증 범위

- 공격 시작, 수비 시작, 로컬 2인, AI 자동 대전의 실제 입력
- 수비 시작 모드에서 역할 교대부터 경기 종료까지 진행 및 전체 상태 재현
- 로컬 첫 제출의 시간 정지, 선택/경로 비공개, 미공개 명령 없는 JSON 저장
- 방향·속도·예상 돌파 방향·수비 간격을 실제 명령으로 전달
- 예약 추가/취소/순서, `Hesitation → Sprint`, `Hesitation → Crossover → Sprint`, 네 번째 드리블 예약 거부
- `ContinueAction` 자동 선택, 추가 드리블 미차감, 적용되지 않는 입력 숨김
- 재시작/모드 변경 확인 취소 및 상태 보존
- 설정 적용, 닫기, 취소, Escape, 배경 클릭, 포커스 복원, 잘못된 시드
- 왼손잡이 설정을 첫 명령과 수비 시작 후 공격권 전환까지 보존
- 리플레이 슬라이더, 재생 종료, 현재 경기 복귀, 저장/불러오기 후 계속 진행
- 잘못된 JSON, 미지원 리플레이, 5MB 초과 파일 거부
- 통계 Worker 시작/진행/중지/재시작/오류/언마운트와 경기 초기화 후 오래된 콜백 무시
- 390px/1440px 너비 설정에서 주요 구역, 이름 붙은 입력, 상태 미터의 DOM 의미 구조

## 테스트 경계

이 테스트는 **jsdom 기반 컴포넌트 통합 테스트**다. 실제 브라우저의 화면 배치, 넘침, 픽셀, 터치 입력, 키보드 포커스 트랩의 가시성 판정, 모바일 화면 품질을 검증했다고 간주할 수 없다. 390px/1440px 사례는 DOM 의미 구조 검사이며 시각적 반응형 QA가 아니다.

파일 저장에 필요한 URL/앵커 API와 jsdom에 없는 `File.text()`를 보완한다. 통계 테스트는 Worker의 생성·메시지·종료 계약만 대체하며, 브라우저 Worker에서 실제 10,000포제션을 실행한 것으로 보지 않는다. 실제 통계 계산은 별도 엔진 통계 명령으로 검증한다. AI/리플레이 타이머는 가짜 시간으로 명시적으로 전진시켜 실제 대기 시간에 의존하지 않는다.
